\begin{abstract}
    Long-running test suites (LRTS) create severe bottlenecks in continuous integration pipelines because developers need rapid feedback even when full test execution can take hours. Our original goal was to build a dependency-aware test prioritization model using method-level dynamic coverage, but extracting stable coverage from legacy large-scale Java/Scala projects proved brittle due to build incompatibilities, dependency conflicts, and instrumentation failures. We therefore evaluate a lighter static baseline: a two-layer Graph Convolutional Network (GCN) over project call graphs, combined with temporal CI metadata, for build failure prediction. Formally, the model predicts whether a build has at least one failing test class, $y=\mathbb{1}[\texttt{num\_fail\_class}>0]$. Across the available metadata datasets, the static GCN fails to provide reliable generalization: on the current datasets, test F1 is $0.509$, below an all-positive baseline F1 of $0.560$. Our analysis shows that the graph embedding acts mostly as a project identifier because each build receives the same static project-level graph representation. This result highlights a key limitation of whole-project static call graphs: without build-specific changed-node and coverage information, graph structure alone is too coarse for robust CI failure prediction.
\end{abstract}
