\section{Conclusion}

In this project, we investigated Graph Convolutional Networks (GCNs) for early build failure prediction in Long-Running Test Suites (LRTS). Our original goal was a dynamic coverage-based test prioritization system, but severe environment conflicts and instrumentation instability in legacy industrial projects forced a pivot to a lightweight static GCN using whole-project call graphs and temporal CI metadata.

The resulting empirical evidence is mostly negative, but informative. On the two current datasets, the static GCN reaches test F1 of only 0.509, below the all-positive baseline F1 of 0.560. The model has high test precision (0.961) but low recall (0.347), meaning it misses most failing builds. Per-project analysis shows that the model identifies nearly all \texttt{kafka} failures but misses almost all failures in \texttt{hadoop}, \texttt{hbase}, and \texttt{james}. This behavior follows directly from the formulation: every build from a project receives the same graph embedding $g_p$, so the graph representation cannot encode build-specific changed methods, covered tests, or affected dependency regions.

The main lesson is that static whole-project call graphs are too coarse for reliable CI failure prediction. Future work should construct build-specific subgraphs, preserve directed and typed edges, and attach node-level signals such as changed-method indicators, coverage, and historical failure information. The challenge is not merely to use a larger model, but to provide the model with graph structure that is mathematically aligned with the build-level prediction task.
